# app-runtime Specification

## Purpose

应用可运行性的行为契约：容器化一键启动、健康检查、数据库迁移就绪与运行环境配置，保障任何人克隆仓库后能以最短路径获得可服务的实例。

## Requirements

### Requirement: 一键容器启动

系统 SHALL 提供单一容器编排命令，同时启动应用服务与其数据库依赖，且应用数据在容器重建后 MUST 得以保留。

#### Scenario: 全新环境一键启动

- **WHEN** 在具备容器运行时的机器上、仓库根目录执行该启动命令
- **THEN** 应用与数据库服务全部启动就绪，应用对外提供 HTTP 服务

#### Scenario: 容器重建后数据保留

- **WHEN** 应用容器销毁后重新启动
- **THEN** 已注册的用户数据仍然存在并可正常登录

### Requirement: 健康检查端点

系统 SHALL 提供健康检查端点，报告应用存活状态与数据库连通性，供容器编排与运维探测使用。

#### Scenario: 数据库连通

- **WHEN** 数据库连接正常时探测健康检查端点
- **THEN** 返回 200 与健康状态标识

#### Scenario: 数据库不可达

- **WHEN** 数据库连接不可用时探测健康检查端点
- **THEN** 返回非 200 状态码与异常状态标识，明确指向数据库故障

### Requirement: 数据库迁移就绪

应用启动时数据库 schema MUST 处于与迁移定义一致的状态：全新环境首次启动时迁移自动完成，存量环境启动时增量迁移安全执行。

#### Scenario: 全新数据库首次启动

- **WHEN** 空数据库环境首次启动应用
- **THEN** 全部迁移自动执行完毕，核心用户表可读写

#### Scenario: 存量数据库增量迁移

- **WHEN** 已有数据的环境启动且存在未应用的迁移
- **THEN** 仅执行增量迁移，既有数据不受破坏

### Requirement: 运行环境配置

系统运行所需的外部配置（数据库连接串、会话签名密钥等）SHALL 通过环境变量注入。缺失必需配置时应用 MUST 拒绝启动并给出明确报错。仓库 SHALL 提供环境变量样例文件。

#### Scenario: 按样例配置启动

- **WHEN** 运维者参照样例文件填写全部必需环境变量后启动
- **THEN** 应用正常启动并完成数据库连接初始化

#### Scenario: 缺失必需配置

- **WHEN** 必需环境变量缺失时启动应用
- **THEN** 应用启动失败，错误信息指明缺失的变量名
